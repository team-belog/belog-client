# 기능 개발

작업의 규모에 맞춰 절차를 조정합니다. 작은 수정도 어떤 동작을 바꾸고 어떻게 확인할지 정한 뒤 시작합니다.

## 작업 순서

1. 요청이나 GitHub 이슈에서 목표, 범위, 완료 기준을 확인합니다.
2. 현재 브랜치와 변경사항을 확인합니다.
3. 대상 화면의 라우트와 레이아웃에서 기능으로 이어지는 흐름을 확인합니다. 비슷한 동작을 가진 기존 구현과 관련 문서를 읽습니다.
4. 코드의 소유 위치를 정합니다. 라우트, 기능 전용 코드, 공용 UI의 기준은 [앱 구조](../architecture/app-structure.md)를 따릅니다.
5. 요청 범위 안에서 구현합니다. 다른 화면이 같은 데이터를 쓰면 변경 후 조회 결과도 확인합니다. 보호 경로를 바꾸면 인증 전후의 진입과 복귀를 확인합니다.
6. [검증](verification.md)에서 변경에 맞는 정적 검사와 사용자 흐름을 확인합니다.
7. 구현한 내용과 검증 결과를 정리합니다. PR은 [Git과 GitHub](../conventions/git.md)의 작성 기준을 따릅니다.

자료에서 확인할 수 없는 요구사항이 사용자 동작이나 API 계약에 영향을 주면 구현 전에 필요한 사항을 확인합니다.

## 완료 기준

- 요청한 동작을 직접 확인했습니다. 화면 변경은 관련 실패와 빈 상태, 모바일 레이아웃도 살핍니다.
- 구조나 규칙이 바뀌었다면 해당 기준 문서에 반영했습니다.
- 실행한 검사와 확인하지 못한 동작을 기록했습니다.
