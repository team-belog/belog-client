# 의존성 관리

의존성을 변경할 때는 잠금 파일, Node.js 호환성, 실제 빌드와 사용 경로를 함께 확인합니다.

## 관리 기준

- 직접 의존성과 허용 버전 범위는 `package.json`에서 관리합니다.
- 실제 설치 버전은 `package-lock.json`으로 고정합니다. 의존성 변경 후 npm이 생성한 잠금 파일과 매니페스트의 diff를 함께 검토합니다.

## 업데이트 순서

1. 변경 대상과 목적을 확인합니다. 보안 업데이트라면 `npm audit` 결과와 공식 권고에서 영향 버전 및 수정 버전을 확인합니다.
2. 대상 버전의 Node.js 요구사항과 피어 의존성을 확인합니다. Next.js, React, ESLint 설정, PWA 플러그인처럼 함께 동작하는 구성은 조합을 검토합니다.
3. 전이 의존성의 보안 수정은 해당 패키지를 사용하는 상위 의존성의 업데이트부터 검토합니다. 별도 npm `overrides`를 적용해야 한다면 영향 버전과 적용 이유를 함께 검토합니다.
4. npm으로 변경을 반영하고 잠금 파일을 갱신합니다. 검토 대상과 무관하게 달라진 버전이 있는지 확인합니다.

## 검증

- `npm ci`로 잠금 파일에 맞게 설치한 뒤 [코드 검사 명령](verification.md#코드-검사-명령)의 lint, 라우트 타입을 포함한 타입 검사, 프로덕션 빌드를 실행합니다.
- 보안 업데이트는 `npm audit`을 다시 실행해 대상 취약점이 해소되었는지 확인합니다.
- 빌드나 브라우저 동작에 영향을 주는 패키지는 [검증 표](verification.md#변경-범위에-따른-검사)의 관련 항목을 확인합니다. 예를 들어 PWA 플러그인 변경은 빌드 후 서비스 워커 등록까지 확인합니다.
