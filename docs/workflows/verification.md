# 검증

검증은 변경 범위와 실패 시 영향을 기준으로 선택합니다.

## 변경 범위에 따른 검사

| 변경 | 확인할 항목 |
| --- | --- |
| Markdown | 변경 파일의 공백, 링크와 참조 경로 확인 |
| 하네스 | 문서 검사와 [하네스 유지보수](../agent/maintenance.md)의 스킬 검사 |
| GitHub Actions 또는 설정 | 문법과 변경 조건 확인, 영향에 따라 이벤트·설정 동작 또는 빌드 확인 |
| TypeScript 유틸 | lint, 타입 검사, 달라진 동작 확인 |
| React 컴포넌트 | lint, 타입 검사, 화면 상태와 상호작용 확인 |
| 라우트 또는 공용 UI·API | lint, 타입 검사, 빌드, 영향을 받는 사용자 흐름 확인 |
| 빌드·PWA·의존성 설정 | lint, 타입 검사, 빌드, 변경된 설정의 동작 확인 |

## 문서와 하네스

```bash
git status --short --untracked-files=all
git diff --check
git diff --cached --check
```

`git diff` 검사는 Git이 추적하는 변경을 대상으로 합니다. `git status`에 `??`로 표시되는 새 문서도 열어 공백, 링크와 참조 경로를 확인합니다.

## 코드 검사 명령

[로컬 개발](local-development.md)의 설치 절차로 의존성을 맞춘 작업 디렉터리에서 필요한 명령을 실행합니다.

```bash
npm run lint
npm exec -- next typegen && npm exec -- tsc --noEmit
npm run build
```

- 타입 검사는 `next typegen`으로 App Router의 생성 타입을 준비한 뒤 `tsc`로 확인합니다. 새 체크아웃에서도 개발 서버나 전체 빌드 없이 라우트 타입을 포함합니다.
- 이전 빌드에서 생성된 서비스 워커와 Workbox 파일이 전체 lint에 포함될 수 있습니다. 소스에서 발생한 경고와 구분합니다.
- 프로덕션 빌드는 Google Fonts의 PT Sans Narrow를 내려받습니다. 빌드가 해당 단계에서 실패하면 폰트 요청과 네트워크 오류를 확인합니다.

현재 GitHub Actions는 PR·리뷰와 `main`의 Vercel 운영 배포에 대한 Slack 알림을 처리합니다. 별도 품질 검사 워크플로와 `npm test` 스크립트가 없는 상태이므로 저장소 검증에는 위 명령과 브라우저 확인 절차를 사용합니다.

## 브라우저에서 확인할 동작

- 변경한 URL이 열리고 뒤로 가기가 의도대로 동작합니다.
- 로딩, 빈 결과, 오류, 비활성, 성공 상태가 상황에 맞게 표시됩니다.
- 모바일과 넓은 화면에서 긴 텍스트와 고정 요소가 겹치지 않습니다.
- 키보드로 주요 동작에 접근할 수 있고 조작 요소의 이름이 명확합니다.
- 정상 요청과 저장 후 재조회가 의도대로 동작합니다. 관련 변경에서는 세션 만료, 업로드 실패, 재시도나 롤백도 확인합니다.
- 콘솔과 네트워크에서 예상하지 않은 오류가 발생하지 않습니다.

### PWA와 웹 푸시

next-pwa는 개발 모드에서 비활성화됩니다. 캐싱 서비스 워커 설정을 바꿨다면 `npm run build`로 워커를 생성한 뒤 `npm run start`에서 등록과 동작을 확인합니다. 웹 푸시 수정 시 지원 환경에서 권한, 알림 수신, 클릭 후 이동과 읽음 처리를 확인합니다.

## 결과 보고

- 실행한 검사와 각각의 결과를 기록합니다.
- 기존 경고와 이번 변경으로 발생한 문제를 구분합니다.
- 외부 연동 환경이나 기기가 필요해 생략한 검사는 이유와 미확인 동작을 함께 적습니다.
