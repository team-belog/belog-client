# Agent Harness 유지보수

## 갱신 시점

- 라우트, 기능 소유권이나 공용 코드 경계가 바뀌었습니다.
- 팀 컨벤션, 패키지 설치, 검증 명령이나 CI가 바뀌었습니다.
- 에이전트에게 같은 프로젝트 규칙을 반복해 설명하거나, 현재 스킬이 실제 작업 순서와 어긋납니다.

관찰한 동작은 코드, 설정과 사용처를 대조해 기록합니다. 도입을 검토 중인 구조는 별도 작업이나
리뷰에서 제안합니다.

## 기록 위치

| 내용 | 기준 위치 |
| --- | --- |
| 저장소 전체에 적용되는 기준과 스킬 선택 | `AGENTS.md` |
| 폴더 소유권, 코딩과 Git 규칙, 실행과 검증 | `docs/`의 해당 주제 문서 |
| 작업을 시작할 때 볼 문서, 판단 순서와 완료 조건 | 해당 스킬의 `SKILL.md` |
| 스킬 표시 이름, 설명, 호출 예시 | 해당 스킬의 `agents/openai.yaml` |

사람이 설명을 순서대로 읽을 수 있도록 한 문단에 한 주제를 다룹니다. 폴더나 구현 이름은 위치가 판단에
필요한 경우 예시로 적습니다. 설치나 검증 명령이 바뀌면 작업 절차 문서에 먼저 반영하고 관련 진입점을
갱신합니다.

스킬의 참고 문서는 저장소 루트 기준 경로로 한 번 안내합니다.
문서 사이의 이동에는 제목이 드러나는 Markdown 링크를 사용합니다.

## 스킬 작성

- 폴더명과 `SKILL.md`의 `name`에 같은 kebab-case 이름을 사용합니다.
- `description`에는 스킬이 적용되는 작업을 적습니다. 본문은 먼저 읽을 기준, 실행 순서와 완료 조건을
  담습니다.
- 기본 호출 프롬프트에 해당 `$skill-name`을 포함합니다.
- 작업 유형이나 판단 단계가 실제로 독립적인 경우에 스킬을 분리합니다. 반복 작업을 자동화할 때는
  실행에 필요한 근거와 검증 방법을 함께 둡니다.
- 저장소 탐색이나 작업 범위 결정처럼 모든 작업에 필요한 절차는 공통 작업 흐름에 둡니다.
  기존 문서나 스킬을 다시 안내하는 역할만으로 새 스킬을 만들지 않습니다.

## 검증

- [검증 가이드](../workflows/verification.md)의 문서 검사 명령으로 공백을 확인합니다.
  새 파일의 내용과 Markdown 링크·제목 앵커·참조 경로도 확인합니다.
- `AGENTS.md`의 스킬 선택 표, 하네스 안내의 스킬 목록, 스킬 폴더, frontmatter 이름과 기본 프롬프트의
  호출 이름이 일치하는지 검사합니다.
- 같은 규칙이 여러 곳에서 다르게 설명되는지 확인합니다. 앱 코드나 설정도 변경했다면 변경 종류에 맞는
  검사를 추가합니다.
- Next.js를 업데이트하면서 에이전트 설정을 건드릴 때는 설치 버전이 지원하는 옵션과 개발 서버 실행 후
  지침 파일에 생긴 변경을 확인합니다.
