# Amplitude 이벤트

Belog는 화면 조회와 제품 동작을 Amplitude 이벤트로 기록합니다. 로그인, 그룹과 만남, Pre-log·Post-log·Bill-log의 주요 흐름에서 명시적으로 이벤트를 전송합니다.

## 실행 조건

- 앱의 클라이언트 Provider에서 초기화합니다. 자식 컴포넌트가 먼저 이벤트를 보내는 경우를 위해 `track` 등 분석 함수에서도 초기화를 확인합니다.
- `NEXT_PUBLIC_AMPLITUDE_API_KEY`가 설정된 브라우저에서 수집합니다. 키가 없는 환경에서는 분석 호출을 건너뜁니다. 로컬 수집 여부는 개발 환경에 설정된 키에 따라 달라집니다.
- SDK의 `autocapture`는 꺼져 있습니다. 수집되는 화면과 동작은 코드에 명시한 이벤트를 기준으로 확인합니다. 분석 키의 설정 위치는 로컬 개발 문서를 참고합니다. [로컬 개발](../workflows/local-development.md)

## 화면 조회

`Page Viewed`는 현재 홈, 그룹 상세, 만남 상세에서 전송합니다. 각 로그 화면은 `Prelog Viewed`, `Postlog Viewed`, `Billlog Viewed` 이벤트를 사용합니다.

| 화면 | 이벤트 | 전송 조건 |
| --- | --- | --- |
| 홈 | `Page Viewed`, `page_name: "home"` | 만남 목록 영역이 렌더링됨 |
| 그룹 상세 | `Group Viewed`, `Page Viewed` | 그룹 상세 데이터가 준비됨 |
| 만남 상세 | `Meetup Viewed`, `Page Viewed` | 만남 상세 데이터가 준비됨 |

조회 이벤트의 데이터가 준비되지 않았으면 `useTrackView`에 `null`을 전달합니다. 각 훅 호출은 컴포넌트가 마운트된 동안 직전에 보낸 이벤트 이름과 속성 조합이 반복되면 전송을 생략합니다.

## 제품 이벤트

- 이벤트를 추가하거나 변경할 때 이름, 전송 조건, 속성을 함께 정합니다. 기존 이벤트를 수정하면 이름과 속성의 호환성을 먼저 확인합니다.
- 동작 완료는 그룹 생성과 핀 변경처럼 요청 성공 시점에 전송합니다. 결과를 모두 집계하는 경우 영수증 OCR처럼 같은 이벤트에 `ocr_status` 값을 넣어 성공과 실패를 구분합니다.
- 제품 ID는 `group_id`, `meeting_id`처럼 문자열로 보내는 기존 패턴을 참고합니다. `has_used_prelog`처럼 사용자 단위로 남기는 상태는 `setUserProperty`에서 관리합니다.
- 프로필 변경 이벤트의 `updated_field`는 바뀐 항목 이름의 배열입니다. 비슷한 이벤트를 추가할 때도 수집 목적에 필요한 속성을 선택합니다.

## 사용자 식별

- Amplitude가 활성화된 상태에서 토큰의 `sub`를 읽을 수 있으면 이를 사용자 ID로 설정합니다. Google 로그인 성공 이벤트는 액세스 토큰 설정을 호출한 뒤 기록합니다.
- 로그아웃 요청의 종료 처리와 회원 탈퇴 성공 처리에서 `resetAmplitude`를 호출합니다. 인증 흐름을 수정할 때는 이 경로들과 이후 로그인에서의 식별 상태를 확인합니다.

## 검증

- 키가 없는 환경에서 로그인과 주요 사용 흐름이 정상적으로 동작하는지 확인합니다.
- 키를 설정한 테스트 환경에서 이벤트를 발생시키고 이름, 속성, 사용자 ID를 확인합니다.
- 화면 조회는 데이터가 늦게 도착하거나 같은 화면이 다시 렌더링될 때 전송 횟수를 확인합니다. 변경 이벤트는 발생 조건에 맞춰 성공과 실패를 각각 확인합니다.
