# 페이지 기능 구현

## 먼저 읽을 기준

- `docs/architecture/app-structure.md`의 라우팅과 보호 경로
- `docs/conventions/conventions.md`
- 대상 페이지, 상위 레이아웃, 해당 기능의 기존 컴포넌트

## 작업 순서

1. 사용자가 들어오는 URL, 상위 레이아웃과 인증 상태를 확인합니다. 로그인 전 접근해야 하는 경로는
   OAuth 콜백과 초대 링크를 참고합니다.
2. 페이지에서 경로 파라미터의 형식과 누락을 처리하고 기능 컴포넌트에 필요한 값을 전달합니다. 가까운
   서버 페이지와 클라이언트 페이지의 경계를 확인합니다.
3. 브라우저 기능이나 사용자 상호작용이 필요한 부분에 클라이언트 경계를 둡니다. 렌더링 방식에 따라 필요한 Suspense 경계도 함께 검토합니다.
4. URL이나 파라미터가 바뀌면 내부 링크와 외부 진입점을 함께 검색합니다. 알림이 여는 경로는 앱과 FCM
   워커 양쪽을 확인합니다.

## 화면 요구사항

화면에 필요한 로딩·빈 결과·오류 상태와 완료 후 이동을 확인합니다. 보호 경로 변경은 직접 진입과
로그인 후 이동, 하단 탭 표시에도 영향을 줄 수 있습니다.

## 완료

대상 URL과 내부 이동, 뒤로 가기, 주요 화면 상태를 확인합니다.
