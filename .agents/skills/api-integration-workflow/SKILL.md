# API 연동

## 먼저 읽을 기준

- [API와 상태](../../../docs/architecture/app-structure.md#api와-상태)
- 대상 기능의 요청 함수와 타입, 조회·변경 훅
- 제공된 API 명세와 실제 응답 형식

## 작업 순서

1. HTTP 메서드, 엔드포인트, 요청·응답 필드와 인증 요구사항을 확인합니다.
2. 브라우저의 백엔드 요청은 기능의 `api`에서 공통 Axios와 엔드포인트 정의를 사용합니다. 서버에서 호출할 때는 해당 요청의 인증과 상태 경계를 확인합니다.
3. 캐시를 직접 갱신할 때는 조회의 전체 키를 사용합니다. 여러 조회를 무효화할 때는 접두 키의 범위를 확인하고, 같은 데이터를 표시하는 화면도 함께 살핍니다.
4. 로딩, 빈 결과, 실패와 성공 상태를 화면 동작에 연결합니다. 낙관적 변경을 사용하면 실패 시 롤백과 재조회 결과를 확인합니다.

## 연동별 확인

- **인증**은 메모리 토큰, 쿠키 기반 갱신, 401 이후 재시도와 이동에 영향을 주는지 확인합니다.
- **업로드**는 백엔드의 URL 발급·메타데이터 등록과 스토리지로 보내는 파일 전송을 구분합니다. 파일은 Presigned URL과 업로드 계약에 지정된 헤더로 직접 전송하고 각 단계의 실패를 확인합니다.
- **오류**는 기존 `ApiError` 형식을 확인하고 사용자에게 필요한 메시지와 재시도 방식을 연결합니다.

## 완료

[검증 가이드](../../../docs/workflows/verification.md)에 따라 정상 요청, 오류 처리, 저장 후 조회 값을 확인합니다.
