# 공용 UI와 레이아웃

## 먼저 읽을 기준

[기능과 공통화](../../../docs/architecture/app-structure.md#기능과-공통화), [스타일링](../../../docs/architecture/styling.md), 대상 또는 유사한 컴포넌트와 사용처를 확인합니다.

## 공통화 판단

공용 버튼과 입력 같은 요소는 `src/components/ui`, 헤더와 하단 탭 등 화면 구조를 담당하는 코드는 `src/components/layout`을 확인합니다. 새 공용 컴포넌트는 실제 사용 화면의 요구를 비교해 책임과 props를 정합니다.

## 작업 순서

1. 기존 사용처와 호출 방법을 확인합니다. 공용 컴포넌트의 기본값이나 이벤트를 변경하면 영향을 받는 화면에서 필요한 동작을 함께 확인합니다.
2. 기존 컴포넌트의 상태 표현과 토큰을 사용합니다. 예를 들어 공용 버튼을 수정할 때는 `variant`, `bare`, `disabled`가 각각 사용되는 위치를 확인합니다.
3. 키보드 포커스, 아이콘 버튼의 접근 가능한 이름, 텍스트와 너비가 달라지는 경우를 확인합니다.
4. 화면에 고정된 UI는 iOS safe area와 헤더·모달·하단 탭 간 겹침을 확인합니다.

## 완료

대표 사용처에서 변경한 props와 화면 동작을 [검증 가이드](../../../docs/workflows/verification.md)에 따라 확인합니다.
