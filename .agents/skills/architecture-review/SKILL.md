# 아키텍처 리뷰

## 기준

[저장소 구조](../../../docs/architecture/repo-structure.md), [앱 구조와 의존성](../../../docs/architecture/app-structure.md), 변경 전후의 실제 사용처를 확인합니다.

## 검토 순서

1. 라우트와 레이아웃의 역할, 기능 코드가 속할 위치가 명확한지 확인합니다.
2. 파일이나 훅을 옮기면 호출자가 새 의존 방향을 따를 수 있는지 확인합니다. 기능 간 연결은 순환 의존과 여러 화면의 캐시 갱신을 살핍니다.
3. 공용 컴포넌트가 제품 기능에 의존하게 되는지 확인합니다. 공통화가 여러 사용처의 실제 요구를 해결하는지 비교합니다.
4. 클라이언트 경계가 상태·이벤트·브라우저 API를 사용하는 곳에 있는지 확인합니다.
5. 구조 변경이 사용자 동작, 기존 데이터나 문서에 미치는 영향을 정리합니다.

## 리뷰 결과

실제 동작에 미치는 영향이 큰 것부터 적습니다. 각 지적에 코드 위치, 문제가 발생하는 조건, 영향과 가능한 수정 방향을 포함합니다. 기존 연결과 이번 변경으로 생긴 문제를 구분합니다.
