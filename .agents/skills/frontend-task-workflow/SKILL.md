# 프론트엔드 작업 흐름

## 입력

작업 목표, 대상 화면이나 기능, 기대 동작을 확인합니다. GitHub 이슈나 디자인이 제공되었다면 해당 요구사항을 함께 읽습니다. 구현, 계획, 리뷰 중 요청된 산출물에 맞춰 작업합니다.

## 스킬 선택

[AGENTS.md의 스킬 선택 표](../../../AGENTS.md#스킬-선택)를 사용합니다. 여러 유형이 섞이면 가장 큰 변경을 담당하는 스킬부터 적용합니다. 예를 들어 결제 등록 화면과 요청이 함께 바뀌면 페이지와 폼의 소유 위치를 정한 뒤 API 계약과 캐시 갱신을 확인합니다.

## 작업 순서

1. 이미 확인한 작업 맥락을 바탕으로 [기능 개발](../../../docs/workflows/feature-development.md)의 범위를 정합니다. 진입점이 아직 확인되지 않았다면 `repo-orientation`을 참고합니다.
2. 구현 스킬을 선택하고 라우트, 기능, 공용 코드에서 바뀌는 위치를 정합니다. 공통화나 의존 방향이 바뀌는 경우 `architecture-review`를 적용합니다.
3. 공용 컴포넌트나 공통 API를 바꾸면 호출하는 화면을 확인합니다.
4. 구현 후 `verify-frontend`로 변경의 영향을 확인하고 결과를 기록합니다.

## 복합 작업 계획

복합 작업은 사용자 동작, 변경할 경계, 기존 코드에 미치는 영향, 검증 방법을 짧게 정리합니다. 문서와 설정 변경은 관련 기준 문서와 기존 파일을 읽고 변경 내용에 맞는 검사를 선택합니다.
